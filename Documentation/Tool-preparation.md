# 工具准备：位置观察不等于执行许可

从 Settings → Tools 或 Mole 的「工具准备…」打开。首次进入不检查磁盘；用户点击检查按钮后，才读取候选路径的元数据。结果只保留在本次应用会话，不保存可执行文件路径、版本、遥测或安装状态。

Mole 兼容验证和升级使用独立的流程。相关功能的精确提交原生验证是合并/发布门槛，通过情况应以对应 CI 及发布记录为准；通用位置观察不代表工具已验证或已升级。

## 通用工具准备页的检查范围

- Mole：推荐的 `~/MoeKit-Mole-V1.58.0-<应用架构>/analyze-go`、`~/.config/mole/bin/analyze-go`、`/opt/homebrew/bin/{mo,mole}`、`/usr/local/bin/{mo,mole}`、`~/.local/bin/{mo,mole}`
- Git：`/opt/homebrew/bin/git`、`/usr/local/bin/git`、`~/.local/bin/git`、`/usr/bin/git`
- 也可通过原生文件选择器选择一个候选文件；不接受命令字符串，不展开 Shell，不搜索 PATH 或遍历目录
- 单次最多 8 个路径；独立 actor 执行 `lstat`，不读取候选文件内容。末端符号链接不跟随；父目录可能正常解析，结果不构成已验证的执行身份

这些是通用工具准备页的限制。Mole 分析窗口另有最多 12 项的安装检测，读取受限安装记录和分析器字节，并可在用户明确点击后联网验证；不能把两个检查器混称为同一功能。

状态含义：

- 未检查：没有结果，不假装未安装
- 此路径未找到：`ENOENT` / `ENOTDIR`；其他安装位置仍未知
- 已找到 · 未验证：普通文件存在执行权限位，或末端存在符号链接。没有核对 ACL、系统执行策略、二进制身份、版本、兼容性、签名或符号链接目标，不能称为可用
- 不支持的候选文件：非普通文件/链接、没有执行权限位、无效或过长的路径
- 无法检查：其他元数据错误，不归类为未安装

`/usr/bin/git` 可能只是 Apple 的工具链启动器。其存在不证明 Command Line Tools 可用；这里不运行它，也不会因版本探测弹出系统安装提示。结果带有观察时间；路径可在检查后变化，历史观察不授权后续执行。通用工具准备页没有执行安装、清理、卸载、维护或 Git status 的入口。

## Mole 的下一步

前往 Mole → Space →「使用 Mole 分析…」，按[新手设置与升级指引](Mole-beginner-setup.md)检查当前版本、来源和具体下一步。MoeKit 优先使用已有安装，不把安装旧版平行分析器作为 Homebrew 不兼容的默认修复。

- Homebrew 1.50.0 缺少 1.56.1 引入的 `scan_status`，应升级原安装；不能因已安装就放行实时分析，也不能误报为未安装
- 官方 1.57.0/1.58.0 与特定 ARM64 Homebrew 1.58.0 在精确字节兼容列表中；完整架构、大小和摘要见[兼容说明](Mole-compatibility-and-upgrade.md#reviewed-artifact-catalog)
- 可识别的其他当前 Homebrew/core major-1 构建需要用户点击联网验证，核对完整 bottle 和其中唯一的常规分析器文件。符合格式要求但未测试的构建还需逐次额外确认，结果只有查看权限
- 较新的安装不会自动降级；自定义 tap、未知来源、版本冲突和其他主版本保持明确状态
- 标准旧版 Homebrew 安装可在独立受控终端审阅固定的 `brew update` → `brew upgrade --formula mole`。显示完整路径和两个命令后，只有用户在聚焦终端内实际按 Return 才开始；通用工具准备观察不授权这次升级

升级会修改 Homebrew/Mole/依赖，取消不能撤销已发生的改变。无 sudo、自动重试、回滚或降级。可靠结束后重新检测，后续文件夹分析另行确认。版本声明、来源验证、兼容性与精确提交测试结果必须分开显示。

## 没有现有安装时的下载指引

分析窗口在未找到现有分析器时提供当前推荐的 [V1.58.0 官方发布](https://github.com/tw93/Mole/releases/tag/V1.58.0)独立分析器下载命令。界面按当前应用架构选择文件，复用执行器的版本、大小、SHA-256 常量；Intel 应用在 Rosetta 下仍显示 amd64 文件。已有自定义位置可先用高级选项选择。

1. 展开并阅读下载命令，复制后自行打开系统终端。复制按钮不会运行命令。
2. 命令以 `umask 077` 和 `mktemp -d` 创建私有下载目录，仅下载指定的官方发布文件，限制 HTTPS/时间/大小，核对精确大小和摘要后才设置执行权限。
3. 验证后独占创建 `~/MoeKit-Mole-V1.58.0-<应用架构>`，通过不覆盖已有文件的硬链接放置分析器。原下载目录保留；已有固定目录保持不变并提示重新检测。
4. 看到 `Mole analyzer ready` 后重新检测。下载不执行 Mole、不替换现有 Homebrew、不修改 PATH，也不安装完整 Mole。

浏览器下载可能带 macOS 隔离标记并被拒绝。应用和指引不移除 xattrs、重新签名或绕过 Gatekeeper；不要换下载方式规避已出现的系统安全警告。`curl --max-filesize` 的流式限制依系统 curl 版本而异，最终精确大小及摘要校验独立执行，不承诺跨版本的硬下载字节边界。

固定发布文件指引避免把安装器成功当成兼容证明。历史审查过的 [V1.57.0 上游安装器](https://github.com/tw93/Mole/blob/6bca4812acd6a3d54ffe97291734c3556a174057/install.sh)可能回退其他发布或本地构建、处理扩展属性及已有 Homebrew 安装；MoeKit 不运行该脚本，也不据此假定其他版本安装器的行为。

Git 仍链接[官方 macOS 安装说明](https://git-scm.com/install/mac)，并提供用户自行执行的 `brew install git` 指引。运行它可能访问网络、安装依赖或更新 Homebrew；应用不自动安装 Homebrew。无需安装 CLI 即可导入 Mole JSON 或使用现有项目元数据发现。

## 生命周期和验证

Demo 禁止读取真实工具位置，不制造示例安装成功。未检查时列表使用 `~/.local/bin`、`~/.config/mole/bin/analyze-go` 等显示路径，避免首次打开或 Demo 截图泄露主目录用户名；主动检查后才展示实际观察路径。

通用检查的取消是合作式的：`lstat` 等待文件系统时无法由 Swift 立即中断。UI 保持正在取消与任务所有权直到返回，不放行第二次检查、不宣称硬超时。关闭、模式切换、取消后的旧结果被丢弃。`WorkspaceStore` 同步更新真实/Demo 代次，选择器返回时核对票据，快速进入再退出 Demo 也使旧选择失效。

测试使用唯一临时目录里的文件、FIFO、链接和可控 provider；候选脚本从不执行，不安装或探测 runner 的真实 CLI。复制命令只能用原生 bash/zsh `-n` 做纯语法验证，不展开或运行。精确提交的 Debug/Release/定向 ASan、原生渲染和交互结果应分别记录。原生渲染应覆盖 Mole/Git 指引、中英文、两种尺寸和深浅色；键盘和 VoiceOver 仍需单独验收。

Mole 分析、在线来源验证和 Homebrew 升级分别受[执行设计](Mole-analysis-execution-design.md)及[兼容和升级协议](Mole-compatibility-and-upgrade.md)约束。这里的元数据观察不能代替任何一项验证或确认。
