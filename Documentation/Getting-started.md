# 上手引导

首次打开健康且为空的真实项目目录时，MoeKit 展示可跳过的原生引导窗口。已有项目、项目目录读取出错，以及显式 `--demo` 启动不会自动弹出。用户可从 Help → Getting started 或 Settings → General → Getting started 重新打开，也可在空项目页、未扫描的进程页打开简短引导。

## 三个入口

- **整理我的项目**：先说明「添加项目」与「在文件夹中发现」的区别、发现后的复查步骤，以及仅选定范围只读和项目列表本地保存；按钮仅进入 Projects。仍需用户主动打开并确认文件夹选择器才读取目录
- **查看进程与端口**：先说明当前用户的可执行文件名称/路径、工作目录、TCP 监听端点，以及不读取参数/环境变量、不发送信号；按钮仅进入 Processes & Ports，仍需显式 Start scan / Refresh
- **先看看示例**：通过原有 Demo 模式切换，展示既有内置样例及持续的 Demo 标识，不往真实项目目录插入示例；不新增扫描或报告导入。已有的 WorkspaceStore 初始化仍加载本地项目目录，不能把 Demo 描述为「应用从不读取任何真实数据」

引导明确当前版本的 Mole 仅导入已有 JSON 报告，CLI 执行、清理、卸载和停止进程尚不可用。项目、任务、进程与 Mole 空状态提供各自真实可用的下一步，不把未知或未执行结果写成零。

## 状态、关闭与重开

- Back 返回入口页；Skip、Escape、原生关闭和完成共用幂等 dismissal。引导未正常关闭即被打断时，下次启动仍可再显示
- 仅持久化一个本地整数 `gettingStarted.dismissedVersion`，无所选目标、时间戳、路径、标识符或遥测；不修改项目目录的结构或内容
- 状态使用独立、可注入的 UserDefaults；生产 App 显式注入 `.standard`，测试使用内存或唯一 suite，并清理 suite
- 重复 Help / Settings 打开会聚焦同一个引导窗口，不重置当前页。完成按钮通过固定 workspace route 打开或聚焦实际工作区，即使用户关闭了最后一个主窗口
- 引导不覆盖目录错误、发现结果复查、清理/停止计划或正在进行的工作；已有模式切换仍取消过时工作。显示引导期间禁用工作区 Find 和 Add project 菜单快捷键

## 验证边界

`GettingStartedTests` 覆盖首次显示、重复启动、跳过/关闭的模型路径、打断、Back/重开、健康/损坏目录原字节保留、Demo 往返、无扫描/无任务/无报告副作用、筛选复位和其他模态状态。

`UISnapshotTests` 为入口、三个详情页及四个空工作区生成英/简中、浅/深色和两种尺寸的应用自有视图渲染。引导内容尺寸为 520×480 与 620×580，主窗口内容尺寸为 960×620 与 1280×800。未向桌面显示窗口，不申请屏幕或辅助功能权限，不读取用户目录，不做实际扫描。渲染测试不会调用真实窗口导航；产物检查只验证完整性、尺寸、语言与覆盖，不取代人工看图或交互验收。

仍需 macOS 手动验收：首次主窗口与引导的前后顺序、原生红色关闭按钮/Command-W/Escape、最后一个主窗口关闭后 Help/Settings 重开、聚焦同一窗口、键盘遍历与 VoiceOver，以及引导期间切到其他窗口再返回。CI 中通过的状态测试和合成图片不应写成已完成这些交互。
