## 先手动安装一次，后续更新交给 Sparkle

本版首次接入固定版本 Sparkle 2.10.0，由它负责检查、下载、签名验证、安装与重新启动。应用菜单、菜单栏图标和 Settings → Updates 共享同一个更新控制器；主动检查时使用 Sparkle 的标准进度、取消、版本说明和安装界面。

**preview.9 及更早版本没有自动安装器，升级到本版仍需手动下载 DMG 或 ZIP，并替换应用。** 旧版的检查更新只能打开 GitHub Release 页面，不能自行安装 Sparkle。先结束当前操作并退出旧应用，再按 macOS 正常安装提示处理；完成首次安装后，后续符合条件的新版本才可通过应用内更新。

安装包继续支持 macOS 15+、Apple Silicon 与 Intel。已有的项目整理、精确进程停止、原生缓存工作流、Mole 分析和单个 Downloads 磁盘映像操作保留各自的复查、确认与恢复边界。

## 分别选择检查、下载安装与预览渠道

- Sparkle 的标准第二次启动提示询问是否允许后台检查；Settings 可随时调整「自动检查更新」
- 「自动下载并安装更新」默认关闭，由用户另行选择。启用后，自动安装通常在退出 MoeKit 时进行；也可以主动查看并立即安装
- 检查和下载偏好交由 Sparkle 保存，应用启动不会重置用户选择
- 预览版默认包含 preview 渠道，用户可在 Settings 关闭。渠道选择单独保存，正在更新时不能切换；切换渠道不授权降级

正在执行原生清理、移入废纸篓、恢复、Git 整理、进程停止或 Mole 分析时，应用会拒绝为更新退出并显示说明。请先完成当前工作；只读扫描、导入报告与任务记录属于本次会话，重启后不保留。

项目目录清单、置顶、偏好和私有恢复记录位于应用包之外。更新替换的是 `MoeKit.app`，不会主动清空这些数据或用户项目，也不会因更新失败而运行清理或重置偏好。

## 固定更新来源与签名验证

更新源固定为本仓库专用 updates 分支上的 [appcast.xml](https://raw.githubusercontent.com/cosZone/MoeKit/updates/appcast.xml)。发布流程先验证并公开不可变版本资产，再创建或非 force 更新仅含 appcast 的分支；后续提交保留分支历史，拒绝重放或降级。

应用内置经审查的 MoeKit 专用 Ed25519 公钥，要求更新源本身已签名，并在解压前验证更新 ZIP 的签名。签名失败不会随时间变成允许未签名更新，也不会自动退回未签名安装路径。发布流程核对输入公钥与源码固定值一致，再验证生成的 feed 与 archive 签名；缺少或不匹配的配置会阻止发布。

未配置、配置无效或更新器启动失败时，仍可主动打开手动 GitHub 版本检查。开发、XCTest、以 `--demo` 或 `--disable-updates` 启动的进程不启动 Sparkle；已运行发布版中的「Use demo data」只切换工作区示例数据，不会关闭应用级更新。

更新请求发往 GitHub，可能携带应用版本，服务端可见连接的 IP 地址；不发送项目／任务内容或系统画像。更新说明禁用 JavaScript。源码配置仅包含公钥，不包含私钥或其他签名凭据。完整行为与信任边界见 [自动更新说明](https://github.com/cosZone/MoeKit/blob/68f05270bd2d493ff695aac8060745c31ab99788/Documentation/Automatic-updates.md)。

## 版本顺序与交付检查

本版完整版本为 `0.1.0-preview.10`，内部 `CFBundleVersion` 为 `2.0.10`；展示用的核心版本仍为 `0.1.0`。更新顺序使用受限的数字版本映射，与 Actions 的运行编号分开。旧版没有自动安装器，其历史构建编号不会参与此更新比较。

发布流程精确核验八份代码对象：主 App、两个原创 helper，以及固定 Sparkle.framework 与其四个嵌套组件。每份代码均检查 arm64／x86_64、标识、开发签名、Hardened Runtime 和空 entitlements；ZIP 往返与 DMG 只读挂载还会复查完整 App 内容。没有捆绑 Apple Git 或第三方 Mole 分析器，也没有新增通用 CLI 执行权限。

交付文件为 DMG、ZIP、`SHA256SUMS.txt`、`BUILD_INFO.json` 与已签名 `appcast.xml`。两种安装包包含同一份 universal Release App；校验和覆盖两种包、构建信息与 appcast。精确 source／run／attempt、包内容和生产签名结果以该版本实际发布记录为准。发布与首次安装步骤见 [开发签名预览说明](https://github.com/cosZone/MoeKit/blob/68f05270bd2d493ff695aac8060745c31ab99788/Documentation/Signed-preview-release.md)。

## 验证范围与安装限制

更新设置、偏好保存、渠道、启动隔离和忙碌退出保护有自动测试；独立原生更新 fixture 在 Apple Silicon 与 Intel runner 上覆盖下载、实际替换、重新启动及篡改／取消／失败拒绝。测试使用自有合成应用、loopback 更新源和非生产测试密钥；fixture 的 ad-hoc 签名未启用 Hardened Runtime，不能据此声称已在真实用户安装的生产签名 MoeKit 上完成更新，也不能证明 Gatekeeper、隐私授权迁移或 Developer ID／公证行为。

**本版继续使用 Apple Development 开发签名，未经过 Apple 公证。** Sparkle 不改变这一分发限制，Gatekeeper 仍可能阻止首次安装或后续运行；DMG 格式也不改变系统信任。不要通过关闭 macOS 安全检查、删除 quarantine 或重签应用解决。完整窗口、键盘、VoiceOver、双架构实机运行与真实目录权限仍需手动验收。

[preview.9 的发布记录](https://github.com/cosZone/MoeKit/blob/68f05270bd2d493ff695aac8060745c31ab99788/website/content/changelog/0.1.0-preview.9.md) 继续描述其原始手动更新能力与四份资产，历史标签和下载不因本版改变。文档网站独立构建与部署，不随 App 安装；广域 Mole 清理、卸载、维护、任意项目删除、任意进程停止和 AI 专用无头浏览器归属识别仍未启用。
