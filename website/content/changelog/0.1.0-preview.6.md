## 使用 Mole 分析一个目录

在 Tools → Mole → Space 选择“使用 Mole 分析…”，选择受支持的直接分析器与一个目录，复查计划并确认后，运行分析、读取真实 JSON 结果并显示覆盖状态。选择文件或打开页面本身不会启动分析，已有 JSON 报告导入仍可独立使用。

- **仅支持 [Mole V1.57.0 官方发布](https://github.com/tw93/Mole/releases/tag/V1.57.0) 的原始 arm64／x86_64 分析器及精确校验和**。Homebrew、自行编译和其他版本不受此适配器支持；`mo` 包装脚本也不能代替直接分析器
- 每次运行前确认选定目录、版本与权限范围，并明确披露私有分析器副本、缓存和临时目录的创建与回收。MoeKit 不自动下载或安装 Mole，不修改其原有缓存，不移除隔离标记或绕过 Gatekeeper
- 分析以普通用户权限运行，**不是 OS 沙箱**。已审查的固定分析路径不修改或删除所选内容，但附带的元数据读取可能超出所选目录；结果不代表全盘物理占用或可回收容量
- 支持取消，并限制分析器运行时间、CPU 和输出；只接受与当前目录匹配且通过路径、身份与覆盖校验的报告。部分覆盖、不可用、失败和取消分别呈现，不伪装成完整成功
- 安装包仅新增 MoeKit 自己编写的进程管理辅助程序，Mole 上游可执行文件仍由用户另行提供；辅助程序与主 App 使用固定标识分别签名并验证

## 工具准备与状态提示

Settings → Tools 和 Mole 的工具准备窗口可主动检查固定常见位置，或选择另一个候选文件。此检查只读取元数据，不执行文件或版本探测；“已找到 · 未验证”不等于兼容或允许执行，也不能替代 Mole 分析的精确校验。

官方安装指引可查看或复制固定命令；复制不会打开终端或自动安装。Homebrew 安装指引不表示其产物符合本版 Mole 分析器白名单。检查结果只保留在当前会话，Demo 不读取真实工具位置。

## 文件、保存与 Demo 边界

- 项目发现以已打开的目录为基础遍历和读取元数据，范围内的目录遍历与元数据读取不跟随符号链接，并限制同时持有的描述符；可观察到的替换或重命名显示为未知或未读，不转而扫描替换目录
- 采用同一协议的 MoeKit 实例通过永久协调锁串行保存项目列表。忙碌与外部更改分别报告，避免把旧快照直接覆盖为新内容；不自动合并或修复。旧版 App、同步工具与任意外部编辑器不一定遵守该锁
- 切换 Demo 会清理临时错误并取消旧任务的界面所有权；旧进度、结果和错误不能覆盖新操作。项目列表存储恢复提示只在真实模式出现，系统错误中的原始路径与解码上下文不直接显示在弹窗中
- 这些检查不是跨文件系统快照或全面的恶意同用户进程隔离，也不保证远程 I/O 硬超时、任意外部写入者之间的无竞争或断电持久性

## 验证与未启用能力

CI 在唯一合成目录中运行官方固定版本分析器，检查正常与部分覆盖结果；另用可控的合成工具和报告验证拒绝路径、取消、资源限制与私有会话回收。发布还需验证固定辅助程序的双架构签名和 DMG／ZIP 一致性，以最终发布记录为准。实际用户目录、完整原生窗口交互、键盘、VoiceOver 和双架构实机仍需手动验收。

清理、卸载、维护、任意进程停止和真实 Git status 仍未启用；实验性 Git 工作不包含在本版。Mole 分析的取消只针对该次运行自己创建的进程组，不是 Processes & Ports 的停止功能。

同仓文档网站补充了搜索参数验证与明确的开发依赖公告例外跟踪；该例外不代表上游漏洞已经修复。网站独立构建和部署，不随 App 安装包交付，也未因此配置公开站点。

继续提供通用 DMG 与 ZIP，使用 Apple Development 开发签名，尚未公证。
