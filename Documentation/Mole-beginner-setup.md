# Mole 新手设置、兼容检查与升级

本文描述 Mole 的设置、兼容检查和受控升级工作流；具体交付版本以发布说明为准。每次功能变更在合并及发布前必须通过[原生验证门槛](Mole-compatibility-and-upgrade.md#native-validation-gate)，源码检查不代表实际升级或交互验收已完成。

## 先使用已有安装

1. 打开 Tools → Mole → Space →「使用 Mole 分析…」。MoeKit 检查少量固定位置，显示已安装版本、来源、路径及验证状态。此时不运行 Mole、Homebrew、Shell 或版本命令，也不扫描要分析的文件夹。
2. 若已有受支持的分析器，选择 Downloads 或其他普通文件夹，点击「复查分析…」。阅读具体目录、版本、私有临时缓存和普通用户权限说明后，才可开始分析。
3. 若版本较旧，优先处理原来的安装来源。不要因为发现了旧 Homebrew 安装，就再安装一份旧版分析器。若显示 Homebrew 升级入口，可按下面的流程审阅命令。
4. 若显示「验证官方 Homebrew 构建」，这是单独的联网比较。点击后会下载官方元数据与 bottle，核对完整压缩包及分析器文件，不安装或执行下载内容。
5. 安装或升级结束后，重新检测。命令成功退出不代表分析器已通过兼容校验；分析文件夹仍需另外确认。

MoeKit 会优先显示已有的 Homebrew 或官方安装。高级选项可手动选择自定义位置；选择文件本身不证明它已通过验证。应用不会自动降级较新的版本，也不会把未知来源变成「可以使用」。

## 看到旧版 Homebrew 1.50.0 时

这表示已找到安装，不是「未安装」。Mole 1.50.0 缺少实时分析需要的 `scan_status` 覆盖信息；上游从 [V1.56.1](https://github.com/tw93/Mole/releases/tag/V1.56.1) 开始明确报告部分或未知的扫描结果。没有这些信息，读不到的大小不能被当作零。

当前计划推荐的版本是 1.58.0。已有 1.57.0 官方原始分析器仍在受审查的兼容列表中；受支持的 1.58.0 官方及特定 ARM64 Homebrew 构建见[兼容列表](Mole-compatibility-and-upgrade.md#reviewed-artifact-catalog)。相同版本号的 Homebrew、自行编译及官方发布文件可能具有不同字节，必须分别验证。推荐版本和来源验证都不能代替精确提交的原生测试证据。

## 在应用内审阅 Homebrew 升级

只有标准 `homebrew/core` 安装、可识别旧版本和符合要求的 Homebrew 文件才提供该入口。自定义 tap、记录冲突、隔离问题和较新版本不会得到通用升级或降级按钮。

1. 点击「使用 Homebrew 升级…」，打开受控终端。MoeKit 先静态检查 Homebrew 文件和主目录，显示两个完整命令。打开窗口不会开始运行。
2. Apple Silicon 标准安装显示 `/opt/homebrew/bin/brew update`，然后是 `/opt/homebrew/bin/brew upgrade --formula mole`。Intel 使用经过检查的 `/usr/local/bin/brew`；若它是受支持的标准别名，则显示实际的 `/usr/local/Homebrew/bin/brew`。始终以窗口内显示的完整路径为准。
3. 阅读影响后，把焦点放在终端内，实际按一次 Return 或小键盘 Enter 才开始。粘贴换行、打开或重开窗口、自动输入和按键重复都不能替你确认。第二步只会在第一步正常成功退出、其受控进程组清理完成后开始。
4. 运行期间可以查看输出、调整窗口、显式复制/粘贴或发送 Ctrl-C。点击停止、关闭窗口或切换 Demo 会请求取消；应用会等待自己启动的进程真正结束，不把「已请求取消」当成「已结束」。
5. 结束后检查结果与重新检测状态。若失败、中断或结果不确定，保留当前信息并先检查安装。应用不会自动重试、恢复、回滚或降级。

`brew update` 会更新 Homebrew 元数据和软件本身，并不只检查 Mole；后续升级可能修改 Mole 及依赖。Homebrew 决定当时安装的最新 formula，命令没有锁定到界面推荐的版本。取消不能撤销已发生的改动。这不是隔离沙盒，使用真实的 Homebrew 和用户主目录；应用不提供 sudo 或密码代填流程。

## 来源已验证，但版本尚未测试

「安装记录显示某版本」「字节来自官方构建」「已通过 MoeKit 测试」是三件不同的事。联网验证只接受 Homebrew 当前发布、与本机 keg 版本及 revision 一致的官方 core bottle；不会下载旧包来替换安装。离线、元数据变化、校验失败、架构不符或文件已改变时，安装仍是未验证状态。

若安装的是兼容格式范围内、尚不在受审查列表中的 major-1 官方 Homebrew 构建，来源验证后每次分析还需额外勾选未测试版本确认。该结果仅供查看，不能获得后续所选条目操作的授权标记。未来其他主版本需要更新适配器，不能靠确认框绕过。MoeKit 不上传本机路径、receipt、文件大小或摘要；联网比较完成的证明只留在内存中，最多有效一小时。

## 确实没有找到分析器时

固定位置没有结果不等于整台 Mac 未安装。先在「高级详情」检查，或选择已有文件。如果确实需要独立分析器，可展开推荐官方版本的下载指引：

1. 查看发布页面与完整下载命令，再点击复制。复制只更新剪贴板，不运行命令。
2. 按 `⌘ Space` 打开「终端」，粘贴、阅读，然后自行按 Return。命令只下载当前应用架构对应的独立官方分析器，不安装完整 Mole，不覆盖 Homebrew，不运行 Mole，不请求管理员密码。
3. 等待 `Mole analyzer ready`，回到 MoeKit 重新检测。出现错误时停止并阅读，不自动重试。

命令用 `umask 077` 和 `mktemp -d` 在主目录创建唯一私有下载目录；下载完成后核对精确大小与 SHA-256，才增加执行权限。随后独占创建 `~/MoeKit-Mole-V1.58.0-<应用架构>`，以不覆盖已有文件的硬链接放置 `analyze-go`。原下载目录保留，两路径共用文件内容。已有固定目录不会被覆盖；如需处理旧目录，应先自行检查或在高级选项选择文件。`curl` 的流式大小限制依系统版本而异，最终精确大小及摘要验证仍独立执行。

应用和指引不清除隔离标记、重新签名或绕过 Gatekeeper。浏览器下载的文件可能带隔离标记而被拒绝；出现系统警告时先检查警告，不要换下载方式规避。

## 检测范围与状态

分析窗口的固定候选集合最多 12 项，目前为 11 项：两个 Homebrew 标准安装路径、官方默认分析器位置、1.58/1.57 独立下载位置，以及六个 `mo`/`mole` 包装命令位置。它不搜索 PATH、不递归遍历主目录。只有规定的安装记录及官方包装文件中的字面版本被限量读取，包装命令从不执行。完整路径列表见[技术说明](Mole-compatibility-and-upgrade.md#discovery-and-static-observations)。

- 可以开始分析：文件匹配受审查构建，且通过架构、类型、权限、所有者和隔离检查；仍需选择目录并逐次确认
- 未找到：只表示被检查的位置没有结果，自定义位置仍未知
- 版本过旧或主版本不支持：已找到安装，但报告格式或适配器不符合要求
- 来源未验证：版本声明可能合适，但文件尚未匹配官方构建
- 来源已验证、尚未测试：需每次额外确认，结果只供查看
- 无法确认：包装命令、记录冲突、缺失分析器、隔离、权限、路径变化等原因保持可见，不统一误报为未安装

## 取消与验收

应用启动不会自行检查真实安装；Demo 禁用真实检查、网络验证和升级。检测、验证、准备、分析及升级共享忙碌状态；取消、窗口关闭、重新检测和模式切换使旧结果失效。重新检测保留选择的文件夹，但清除过期分析器、确认与结果。阻塞中的文件系统调用不一定能立即中断，应用保留任务所有权直到实际返回。

测试应使用唯一临时目录、合成 provider 和受控的假 Homebrew 程序。真实官方分析器只能用于隔离的原生 CI fixture；测试不得升级用户的 Homebrew 或扫描真实用户目录。英文/简中、深浅色、不同窗口尺寸的原生渲染，以及实际键盘、VoiceOver、粘贴、重复确认、取消与关闭交互分别验收。源码检查或便携 C 测试通过不能代替这些结果。
