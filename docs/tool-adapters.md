# 本机工具适配契约

状态：planned。本文是产品与实施蓝图，尚无可运行应用或已验证的执行能力。

## 本机工具适配器

目标是使用用户已经安装的工具，不要求重复安装，不静默下载安装，不从项目目录或不可信 PATH 项自动选取同名程序。

### 统一契约

每个适配器都应提供下列可审查信息，而非仅保存一段 shell 命令：

| 契约 | 必须包含的内容 |
| --- | --- |
| Discovery | 已验证的 executable 绝对路径、真实路径/身份、发现来源；同名工具消歧；用户可明确选择 |
| Version | 版本信息、供应方、已测试区间；版本无法识别时的降级行为 |
| Capabilities | 分别声明发现、检查、精确路径范围、预览、执行、取消、结果核验、恢复；每项为已验证/不支持/未知 |
| Output contract | 经验证的结构化格式或特定版本解析器；输出不匹配立即停止，不靠屏幕文本猜测删除目标 |
| Side effects | 是否联网、执行 hooks/配置脚本、写元数据、提权、移动到 Trash、永久删除或清理额外对象 |
| Planning | 能否给出完整、精确、稳定的影响集合；预览是否真正不修改；参数对应哪个具体版本 |
| Execution | 允许的 executable、参数形状、cwd、受控环境、时间预算、输出上限与精确目标 |
| Verification | 操作后如何重新确认目录、ref/登记、失败项和恢复材料；退出码不能作为唯一证据 |
| Recovery | 明确恢复覆盖与限制；不支持时返回不可用，而非“撤销”占位按钮 |

默认先读取本机存在性信息，再由用户启用工具；版本/能力探测只使用已经审查过的探测方式。升级、更换可执行文件或解析结果漂移后重新验证能力，旧审核计划失效。

**不能预设所有 CLI 都有 JSON、真正 dry-run、单路径过滤或稳定 API。** 一个参数叫 `--json` 不代表只读；一个选项叫 dry-run 也必须确认其实际行为。没有可靠范围或预览时，只提供说明/由用户主动打开工具，不能把应用自己的候选列表冒充底层工具的执行清单。

调用使用 Foundation Process 的 executable URL 和参数数组，不拼接 shell 字符串，不运行任意命令模板。需要 shell 函数、别名或未经审核脚本的能力不直接接入。[Apple Process](https://developer.apple.com/documentation/foundation/process)

### 旧版本兼容场景示例（尚未适配测试）

例如 Git 2.51、Mole 1.50 和 Worktrunk 0.8.1 可作为旧版本兼容验证场景；它们不构成已通过的支持矩阵。不能把较新官网文档中的功能直接视为旧版本支持。每个具体安装版本都需逐项验证，缺失/未知能力关闭执行，不以自动升级或安装解决。应用面向任何机器都从发现和能力检测开始。

### 各工具的职责

**Git：基础、优先实现。** 负责真实 repository/worktree/ref 状态与受约束的原生操作。使用已验证的 porcelain/NUL 及显式字段格式，按字节解析特殊路径；后台检查控制可选写锁和网络副作用。审查 fsmonitor、filters、hooks 等执行面，不能仅凭命令名声称完全只读。不绕过 ownership 检查或修改 `safe.directory` 来“修好”访问。

**Mole CLI：可选的本机开发清理能力。** 用户启用后检测实际安装版本与功能，重点评估项目产物清理的可复用部分。官方 CLI 的产物 purge 与 worktree 退役是不同功能；不能把删除依赖目录理解为删除 worktree。CLI 与另售原生 app 也不是同一个代码库或接口。[Mole CLI](https://github.com/tw93/Mole)

Mole 接入首先做一次隔离环境验证：确认准确命令形状、扫描根、配置影响、预览输出、执行范围与删除语义。只有能把审核范围可靠映射到实际动作时才开放集成执行；否则保持“检测到工具 + 能力说明 + 用户主动在 CLI 操作”。不把宽范围的 `mo clean`、`mo purge` 或其它总清理入口直接绑定到某个项目的确认按钮，不修改用户 Mole 配置来偷偷缩小/扩大范围。

**Worktrunk：后续可选增强。** 评估其库存、集成状态及高级 squash/合并证据；应用自身的保护规则仍然适用。必须确认工具身份是 max-sixty/worktrunk、具体版本、hooks、配置和进程处理行为，再考虑执行型集成。首个接入可限定为只读证据。[Worktrunk](https://worktrunk.dev/)

**gfold：后续可选发现加速。** 在用户选择的根目录内提供仓库发现或库存线索，由 Git 验证仓库身份与关联 worktree；不把其结果当成删除许可，也不假定能发现根目录之外的所有 linked checkout。[gfold](https://github.com/nickgerace/gfold)

### 不接成通用插件执行器

首版适配器在应用中显式实现，附带能力矩阵与测试。暂不开放任意 shell 插件、社区脚本自动下载或自行决定文件范围的后台任务。

### 参数风险示例

工具的 wipe/remove 与 status 是不同动作，JSON 只是输出形态，不能把执行入口当成只读检查。优先评估明确的状态入口，并针对工具身份、实际版本、配置及 hooks 验证；不同工具的同名子命令不能互相套用。Mole CLI 的产物 purge 与其原生 app 的 worktree preview 功能分别评估，不混用文档或命令。

具体例子：[git-wipe](https://github.com/noirbizarre/git-wipe#usage) 的公开文档说明 `git wipe --json` 隐含 `--yes`，会进入执行流程；只读库存入口是 `git wipe status`，其 JSON 形态应按对应版本另行验证。这是独立工具，不是 Git 内置子命令，也不是 Worktrunk。此处仅记录接口风险，不代表已安装、已支持或允许调用。
