## 原生 UI 原则

- 用 SwiftUI、SF Symbols、系统字体、列表、表格、分栏导航和设置控件表达信息层级；适应浅色/深色、动态字号与辅助功能。
- 粉蓝仅用于品牌与温和强调；警告、失败、删除等使用语义颜色和文字，不用品牌色淡化风险。
- 参考 MoePeek 的 regularMaterial、统一内边距、紧凑卡片和适度圆角经验；实际尺寸按 MoeKit 信息密度与系统布局验证。参考中浮窗圆角为 12pt、统一水平内边距为 14pt，不作为所有页面的固定值。
- 清理候选与 Git 工作区按用途分组，详情就地展示证据，危险动作进入专门审阅面板。
- 工作区详情分别展示修改、未跟踪、ignored、提交、远程和关联 worktree 的状态，不以单一绿色“安全”徽章代替证据。
- 所有扫描阶段可取消，并解释权限不足、未知大小与工具缺失；失败时保留可理解的下一步。

## 操作审阅

在执行前展示真实路径、所属仓库/工具、候选理由、受保护数据、预计范围、所选动作与恢复条件。刷新后计划失效或文件发生变化时重新检查。删除 checkout 与删除分支分别选择；默认不预选危险动作。预计大小不承诺实际释放空间，移动到废纸篓也不宣称空间已释放。

## 完整界面与交互蓝图

### 主窗口

采用 SwiftUI 的原生窗口、分栏导航、表格、工具栏、搜索和检查器；必要时使用 AppKit 补足文件选择、Finder 定位、复杂表格行为与系统集成。

- **左栏：** 工作区、已保护项目、用户添加的目录/分组、操作历史。工具连接放在 Settings，避免占用主工作流
- **中央：** 按项目归组的可排序列表。默认只显示名称/分支、状态摘要、空间估算和最近检查；更多列由用户选择
- **右侧检查器：** 按需展开选中项的路径、Git 证据、产物明细、保护原因和可执行动作
- **工具栏：** 添加目录、刷新、搜索、筛选、审核已选项目。扫描进度和取消入口始终可见
- **审核窗口：** 单独展示精确路径、动作、执行工具、影响、恢复条件和预计空间变化，确认后才执行

提供“可审核”“需处理”“已保护”三类筛选。状态徽标解释事实，不使用绝对的“安全”标签或不透明风险分数。高级证据、命令参数和原始诊断折叠在详情中。

### 延续 MoePeek 的已验证设计语言

开发参考为 [MoePeek](https://github.com/cosZone/MoePeek)，早期检查基线是 v0.19.2 / `ee75bd7`（当前工程参考已更新至 v0.20.0 / `f12d421`）。已观察到的 GUI 约定包括原生分栏设置、系统蓝与语义颜色、系统字体、紧凑卡片、`.regularMaterial`、12 pt 浮动区域圆角及 14 pt 内边距。MoeKit 将从这些实际约定出发，按工作区列表和审核界面的用途调整；这些数值是参考起点，不要求全界面机械照搬。

MoePeek 现有图标采用粉蓝粉彩、淡紫角色、紫色轮廓和腮红。MoeKit 已包含新的粉蓝整理主题首版概念图；AppIcon 包装、小尺寸与系统遮罩验证尚未实施。GUI 保持系统语义色和可读性，粉彩主要用于品牌图标与克制的点缀。

### 两条清楚的操作路径

**清理产物：** 选项目 → 查看候选目录与依据 → 选择具体路径 → 审核重建成本与恢复方式 → 清理 → 核验。

**退役工作区：** 选 worktree → 检查本地文件和历史 → 明确保留分支/备份选择 → 审核 → 重新检查 → 通过 Git 移除 → 核验登记与目录状态。

不要把“清缓存”“移除 worktree”“删除分支”“清理失效登记”合成一个含义不明的按钮。默认操作文案应清晰，例如“审核 3 个目录”或“移除工作区并保留分支”。

### 视觉与交互要求

- 遵循 macOS 的排版、间距、窗口材质和系统控件；少量强调色用于选中态和主要动作
- 浅色与深色模式同等设计，避免依赖纯红/绿表达状态
- 支持键盘导航、多选、快捷键、VoiceOver、增大对比度与减少动态效果
- 长路径可复制和展开，控制字符可见化；重要状态不能只藏在悬停提示里
- 空状态引导选择项目目录；权限不足、目录离线、扫描不完整分别有自己的说明
- 从缓存快速呈现列表，新扫描结果渐进更新；主线程不做 Git 调用或目录大小遍历
- 大小尚未算完时显示“估算中/部分结果”，不显示误导性的零字节
