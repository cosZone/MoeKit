# 开发产物分类与清理

状态：planned。本文是产品与实施蓝图，尚无可运行应用或已验证的执行能力。

## 产物分类与清理

产物规则应有版本、适用工具链、识别依据、明确路径、排除规则、重建说明和测试用例。目录名本身不足以证明内容可丢弃。

| 分类 | 典型候选 | 默认处理 |
| --- | --- | --- |
| 构建输出 | 经项目与内容检查后的 `.build`、`target`、部分 `dist` | 可供审核；不自动选择，不因名称匹配直接删除 |
| 可重新下载的依赖 | `node_modules`、`Pods`、部分虚拟环境 | 更高成本提示；需网络/锁文件等条件，首版可仅展示 |
| 共享开发缓存 | Xcode、包管理器等工具维护的缓存 | 后续单独适配，说明影响的多个项目和工具状态 |
| 本地数据 | `.env`、数据库、下载素材、笔记输出、自定义目录 | 默认保护；忽略文件不等于可重建产物 |
| 归档项目 | 包含源代码、Git 历史和必要本地文件的项目 | 后续专门休眠流程，验证归档后才考虑移除原目录 |

产物清理也要检查被跟踪内容、嵌套仓库、符号链接边界、活跃构建及规则外文件。对无法证明范围的目录保持人工检查，不把 `.gitignore` 当作授权清单。

原生实现只承担必要的库存、有限规则和精确操作，不重新实现完整系统清理器。底层工具能提供可靠且可约束的能力时，通过适配器接入。
