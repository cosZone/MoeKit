## 实际分析一个文件夹

在 Tools → Mole → Space 点击「使用 Mole 分析…」，依次选择已安装的直接分析器和一个本地文件夹，点击「复查分析计划…」。只有在确认范围、版本、临时文件与权限说明后点击「开始分析」，才会启动工具。

- 首个适配器只接受 [Mole V1.57.0 官方发布](https://github.com/tw93/Mole/releases/tag/V1.57.0) 的原始分析器及精确校验和。官方脚本安装的常见路径是 `~/.config/mole/bin/analyze-go`
- Homebrew、自行构建及其他版本暂不匹配该校验；找到文件不代表兼容。不会运行 `mo` 包装脚本、自动安装、更新、提权或移除隔离标记
- 工具使用普通用户权限运行，没有 OS 沙箱。已审查的分析分支不修改或删除所选内容，但附带元数据读取可能超出目录；不承诺全盘物理占用或可回收容量
- 每次确认会说明私有分析器副本、缓存和临时目录的创建与回收；原有 Mole 缓存不被使用。根目录及与私有会话目录重叠的范围不受支持
- 可取消分析；分析器运行时间、CPU 与输出有上限。完整、部分、不可用与失败分别呈现；无效或越界报告不会伪装成成功

该分析入口已随 [0.1.0-preview.6](/changelog/0.1.0-preview.6) 发布；该版本记录包含精确源码、测试与签名验证范围。后续源码变化不自动计入旧安装包。

## 导入报告

在 Tools → Mole → Space 选择一份 Mole `analyze --json` 报告。应用只读取你选择的 JSON，文件上限为 16 MiB。

导入不会运行 Mole，也不会根据报告中的路径继续读取或修改磁盘。MoeKit 不负责在当前阶段安装上游 CLI。

## 工具准备

从 Mole 的「工具准备…」或 Settings → Tools 打开工具准备窗口。点击「检查常见位置」才会检查 Mole / Git 的固定候选路径，也可以用「检查其他文件…」选择自定义安装文件。检查只读取元数据，不运行文件或版本命令。

- 「此路径未找到」只说明该候选位置没有文件，不代表机器上未安装工具
- 「已找到 · 未验证」不会证明文件属于 Mole / Git、版本受支持或可以安全运行；符号链接的目标也未检查
- 非普通文件、缺少可执行权限与无法读取分别说明，不把错误当作缺失

以下精确下载指引已随 [0.1.0-preview.7](/changelog/0.1.0-preview.7) 发布，preview.6 安装包不包含这项改进。

Mole 指引对应受支持的 V1.57.0 官方分析器，显示适合当前应用架构的官方下载链接、大小校验和 SHA-256。「复制下载命令」只更新剪贴板；你可以先展开查看，再自行粘贴到终端运行。命令在主目录新建私有文件夹，下载固定发布文件，核对大小和 SHA-256 后才添加执行权限，最后打印 `analyze-go` 路径。它不会运行分析器、执行上游安装脚本、覆盖现有安装或修改 PATH。成功或失败后，新文件夹都会保留供你检查。

回到「使用 Mole 分析…」选择终端输出的文件路径。已有官方脚本安装的常见路径为 `~/.config/mole/bin/analyze-go`；安装位置不代表通过验证。Homebrew、其他版本与自编译文件目前不兼容，因此 Mole 准备页不再默认推荐 Homebrew 命令。

浏览器下载可能带有 macOS 隔离标记，MoeKit 会拒绝这类文件。应用和复制的命令都不移除隔离标记或绕过 Gatekeeper；遇到安全警告时，不应通过换下载途径来规避。每次分析仍重新校验实际文件并要求确认。

Git 准备页仍提供其官方 Homebrew 指引。Demo 不检查真实工具。项目发现与 JSON 报告导入仍不依赖 CLI 执行。

## 单个 Downloads 磁盘映像与恢复

[0.1.0-preview.7](/changelog/0.1.0-preview.7) 新增一个独立的原生操作入口。对当前用户真实 Downloads 目录完成受支持的 Mole 分析后，从当前结果选择一个直属常规 `.dmg`，复查路径、大小与检查边界，并确认安装及使用已经结束，才会移到 macOS 废纸篓。分析结果只是选择线索；导入 JSON、Demo 或单独选择路径不能授权操作。

每次操作要求本地内置 APFS，重新检查文件与目录身份、所有权／ACL、项目保护、当前用户文件描述符与 fileport，以及完整空磁盘映像清单。`.pkg`、项目、worktree、链接、云占位、嵌套／批量目标、外置或网络卷，以及未知／变化的证据均不受支持。只可自行推出自己打开的映像；系统映像应保持原状，它们存在时操作可能持续不可用。MoeKit 不自动推出映像。

这些检查不证明全局未使用：内存映射、其他用户、系统服务与检查后新出现的使用不在证明范围内。移到废纸篓不立即释放空间。启动或打开页面不会自动扫描；主动准备计划只进行只读复查，不创建恢复记录或移动文件。

确认后的操作保留私有记录。恢复需重新复查并另行确认，回到原 Downloads 路径时绝不覆盖已有目标；废纸篓被清空、身份或卷改变时可能不可恢复。不确定结果保留数据并停止，不自动重试。Finder 的“放回原处”可能指向内部暂存位置，应通过 MoeKit 的凭据恢复入口复查原路径。

这项操作不提供广域 Mole 清理、永久删除或清空废纸篓；不保证抵御恶意同用户进程竞争。完整限制见 [原生文件操作设计](https://github.com/cosZone/MoeKit/blob/main/Documentation/Installer-trash-design.md)。

## 多缓存原生操作与恢复

[0.1.0-preview.8](/changelog/0.1.0-preview.8) 新增 **Tools → Mole → Cleanup**：选择文件夹后主动检查，从候选中选择精确缓存，复查完整内容清单并明确确认后移入原生 macOS 废纸篓。它使用独立的原创原生适配器，不运行 Mole 的广域 `clean`／`purge`，不根据导入报告直接删除内容。

- 支持当前用户 `~/Library/Caches` 的直属缓存，或当前用户主目录内其他所选位置带有效标准 `CACHEDIR.TAG` 的直属候选目录；标记和位置只是证据，仍须确认工作负载已停止且内容可重新生成
- 仅限内置本地 APFS、完整且可读的清单；每批最多 16 个缓存、25,000 个清单项目，并受时间预算约束。祖先目录不含符号链接；清单内的链接仅作为链接处理，不跟随目标
- 项目／worktree／Git、凭据、安全及系统缓存、MoeKit 控制目录、云占位和未知权限／ACL／卷状态保持保护；`node_modules`、`build` 等名称本身不授权清理
- 准备计划只读，确认有效期 120 秒且仅可使用一次；选择、目录、项目保护、取消或模式变化使旧计划失效。移入废纸篓前重新检查，逐项报告结果，错误时停止后续项目
- 恢复需主动读取本应用的操作记录，重新复查并另行确认原路径恢复；目标已存在时拒绝，不覆盖或合并
- 永久删除只接受已完成且内容未变的缓存记录，另行展示清单并确认不可恢复；重新捕获、逐项核对身份后仅移除已确认清单，不清空整个废纸篓。部分／未知结果保留可见记录，不自动重试

移入废纸篓不释放占用存储；永久删除也不保证立即等量回收物理空间，因为打开文件、硬链接、APFS 快照／克隆可能保留物理块。此工作流面向已停止相关工作负载的合作式本地使用，不是 OS 沙箱，也不保证抵御恶意同用户进程竞争。完整实现与限制见 [原生缓存清理设计](https://github.com/cosZone/MoeKit/blob/b0bdd59ff672efe16a23a20b422e0e433179be11/Documentation/Native-cache-cleanup.md)。

## 四种覆盖状态

| 状态 | 含义 |
| --- | --- |
| known | 已知的报告覆盖 |
| partial | 只覆盖部分范围 |
| unavailable | 数据无法取得 |
| unknown | 上游没有提供足够的覆盖信息 |

unavailable 不显示为零字节；unknown 保留上游报告值，并标注覆盖未知，不能据此认定目录为空。旧报告没有覆盖字段时，按 unknown 处理。

## 哪些数值不能相加

概览位置可能互相重叠，不能直接相加当作完整磁盘分区。只有非概览、覆盖已知、行唯一且总和一致时，才会显示可相加的比例。

报告里的大小不等于物理磁盘占用，不等于可以安全删除的大小，也不等于实际能回收的空间。导入时间不是测量时间。

## 其他 Mole 工作区

原生 Cleanup 已按上述范围开放。Apps、Maintenance、Status 仍保留工作区结构与能力提示；广域 Mole 清理、卸载、维护和实时系统指标尚未实现，没有任意命令执行入口。

已导入的报告只保留在本次应用进程中。Demo 示例持续带有标识，不会冒充你的真实磁盘测量。
