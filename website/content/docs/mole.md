## 实际分析一个文件夹

在 Tools → Mole → Space 点击「使用 Mole 分析…」，依次选择已安装的直接分析器和一个本地文件夹，点击「复查分析计划…」。只有在确认范围、版本、临时文件与权限说明后点击「开始分析」，才会启动工具。

- 首个适配器只接受 [Mole V1.57.0 官方发布](https://github.com/tw93/Mole/releases/tag/V1.57.0) 的原始分析器及精确校验和。官方脚本安装的常见路径是 `~/.config/mole/bin/analyze-go`
- Homebrew、自行构建及其他版本暂不匹配该校验；找到文件不代表兼容。不会运行 `mo` 包装脚本、自动安装、更新、提权或移除隔离标记
- 工具使用普通用户权限运行，没有 OS 沙箱。已审查的分析分支不修改或删除所选内容，但附带元数据读取可能超出目录；不承诺全盘物理占用或可回收容量
- 每次确认会说明私有分析器副本、缓存和临时目录的创建与回收；原有 Mole 缓存不被使用。根目录及与私有会话目录重叠的范围不受支持
- 可取消分析；分析器运行时间、CPU 与输出有上限。完整、部分、不可用与失败分别呈现；无效或越界报告不会伪装成成功

该分析入口已随 [0.1.0-preview.6](/changelog/0.1.0-preview.6) 发布；该版本记录包含精确源码、测试与签名验证范围。后续源码变化不自动计入旧安装包。

## 导入报告

在 Tools → Mole → Space 选择一份 Mole `analyze --json` 报告。应用只读取你选择的 JSON，文件上限为 16 MiB。

导入不会运行 Mole，也不会根据报告中的路径继续读取或修改磁盘。MoeKit 不负责在当前阶段安装上游 CLI。

## 工具准备

从 Mole 的「工具准备…」或 Settings → Tools 打开工具准备窗口。点击「检查常见位置」才会检查 Mole / Git 的固定候选路径，也可以用「检查其他文件…」选择自定义安装文件。检查只读取元数据，不运行文件或版本命令。

- 「此路径未找到」只说明该候选位置没有文件，不代表机器上未安装工具
- 「已找到 · 未验证」不会证明文件属于 Mole / Git、版本受支持或可以安全运行；符号链接的目标也未检查
- 非普通文件、缺少可执行权限与无法读取分别说明，不把错误当作缺失

官方安装说明可以打开查看；「复制命令」只更新剪贴板，不自动安装、不打开终端。手动运行 Homebrew 命令可能安装依赖、访问网络与更新 Homebrew。Demo 不检查真实工具。项目发现与 JSON 报告导入仍不依赖 CLI 执行。

## 四种覆盖状态

| 状态 | 含义 |
| --- | --- |
| known | 已知的报告覆盖 |
| partial | 只覆盖部分范围 |
| unavailable | 数据无法取得 |
| unknown | 上游没有提供足够的覆盖信息 |

unavailable 不显示为零字节；unknown 保留上游报告值，并标注覆盖未知，不能据此认定目录为空。旧报告没有覆盖字段时，按 unknown 处理。

## 哪些数值不能相加

概览位置可能互相重叠，不能直接相加当作完整磁盘分区。只有非概览、覆盖已知、行唯一且总和一致时，才会显示可相加的比例。

报告里的大小不等于物理磁盘占用，不等于可以安全删除的大小，也不等于实际能回收的空间。导入时间不是测量时间。

## 其他 Mole 工作区

Clean、Apps、Maintenance、Status 目前保留工作区结构与能力提示。清理、卸载、维护、实时系统指标尚未实现；没有命令执行入口。

已导入的报告只保留在本次应用进程中。Demo 示例持续带有标识，不会冒充你的真实磁盘测量。
