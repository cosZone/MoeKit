## 当前已实现

| 能力 | 行为 | 不包含 |
| --- | --- | --- |
| 项目工作台 | 原生 Table、搜索与排序、inspector、置顶、Finder 定位 | 通用实时 Git status、项目脚本运行 |
| 项目发现 | 用户选目录后，有限度地读取 Git 布局并勾选导入 | 全盘自动扫描、跟随符号链接 |
| 项目持久化 | 保存名称、路径、置顶、最近 Finder 定位时间 | 云同步、项目文件修改 |
| Mole Space | 导入 analyze JSON，或逐次确认后用精确官方 V1.57.0 分析器分析一个目录 | 任意版本／命令、清理、可靠可回收空间计算 |
| Downloads 磁盘映像 | 从当前真实分析中选择一个受支持的直属 `.dmg`，独立复查、确认移入废纸篓；凭私有记录另行确认恢复 | 导入／Demo 授权、覆盖恢复、批量或永久删除、清空废纸篓 |
| 原生多缓存操作（preview.8） | 精确批次移入废纸篓、另行确认的不覆盖恢复与记录内缓存永久删除 | 广域清理、项目删除、清空废纸篓、物理空间回收保证 |
| Processes & Ports | 主动读取当前有效用户的进程与 TCP 监听端口 | 自动轮询、命令参数、环境变量、CPU/内存监控 |
| 精确进程停止（preview.8） | 复查后单次确认 SIGTERM；仍存活同一身份另行确认 SIGKILL | 受保护目标、AI 浏览器归属、按名称/整个组停止 |
| Git 整理（preview.9） | 单独确认干净 linked worktree 退役、已合并未检出 loose 分支移除与会话内恢复 | force、永久删除、空间回收、任意布局或通用实时 status |
| 应用入口（preview.9） | 独立 Dock／菜单栏图标设置、同时隐藏时从 Finder／Spotlight 重开恢复 | 关闭窗口即退出、所有任务必然后台继续的保证 |
| 签名应用更新（preview.10） | Sparkle 后台检查、可选的自动下载安装与预览渠道；不可用时可主动查看手动版本检查 | 从 preview.9 自动引导安装、未签名降级、Developer ID／公证或实机权限迁移保证 |
| Tasks | 本次会话的任务、取消、结果与诊断 | 跨重启的任务历史 |
| Demo | 显式开启，持续标识，与真实状态隔离 | 启动即伪造真实结果 |

实际 Mole 分析仅支持精确匹配的官方原始二进制，Homebrew 和自编译版本暂不受支持。它以普通用户权限运行，不是 OS 沙箱；每次确认披露私有分析器副本、缓存和临时目录的创建与回收。取消仅管理该次分析自己创建的进程组，与 Processes & Ports 的逐次确认停止相互独立。

原生 `.dmg` 操作已随 [preview.7](/changelog/0.1.0-preview.7) 交付，要求本地内置 APFS、完整空映像清单及身份／ACL／项目保护等检查；拒绝未知证据。当前用户句柄观察不证明全局未使用，系统映像可能使功能不可用；移入废纸篓不立即释放空间。详细确认与恢复限制见 [Mole 页面](/docs/mole)。

[preview.8](/changelog/0.1.0-preview.8) 已交付精确进程停止与原生缓存工作流；preview.7 不包含这些新增能力。缓存清单与位置不能证明内容可丢弃，必须逐次确认；永久删除需要另一次不可恢复确认，仅针对本应用已完成的缓存记录。浏览器与共享服务停止、无头浏览器归属仍未开放。

[preview.9](/changelog/0.1.0-preview.9) 新增上表的 Git 整理、应用入口与手动更新。退役保留分支，移除分支必须另行确认；数据留在恢复目录，不释放空间，恢复不覆盖。preview.8 不包含这些能力，完整支持子集与证据见版本记录。

[preview.10](/changelog/0.1.0-preview.10) 已交付首个 Sparkle 更新器及签名 feed，旧版仍需先手动安装一次。自动下载安装默认关闭；项目清单、偏好与恢复记录位于应用包之外。双架构合成更新测试与真实生产签名／公开资产验证已完成，实际用户安装后的生产更新、Gatekeeper 与隐私授权迁移仍需验收。

## 尚未实现

- 任意 CLI 命令或版本的执行管线
- 广域 Mole clean／purge、卸载与维护操作
- AI 专用无头浏览器的可靠归属与清理
- 实时系统指标、后台自动扫描
- 提权、特权辅助进程
- 任意第三方脚本或二进制插件加载
- 持久任务历史
- Developer ID／Apple 公证分发，以及正式版多条目／独立频道更新策略

原生 Cleanup 只按上述已审查范围开放；Apps、Maintenance、Status 等保留的工作区入口不代表广域清理、卸载、维护或实时指标已经开放。

## 怎样看验证记录

检查某项结果时，必须同时核对源码 SHA 和该提交的 [Actions](https://github.com/cosZone/MoeKit/actions) 记录。

- 结构检查通过，不代表 Swift 可以编译
- Swift 测试通过，不代表界面、VoiceOver 或真实权限场景已验收
- 一个架构上的测试通过，不代表两种芯片都经过实机测试
- 应用短时间保持运行，只是存活检查，不是完整操作验收
- 签名成功，不代表已经公证或发布

原生视觉、辅助功能、双架构实机体验和真实进程读取覆盖仍需手动检查。完整清单见 [仓库验收文档](https://github.com/cosZone/MoeKit/blob/main/Documentation/Verification.md)。
