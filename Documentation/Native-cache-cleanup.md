# 原生缓存批量清理

当前源码新增 Tools → Mole → Cleanup 的真实批量缓存操作。此页描述源码能力；未发布版本的验证状态以对应 PR 的精确提交 CI 为准。preview.7 不包含此工作流。

## 如何使用

1. 选择“用户缓存”，或选择包含缓存子目录的文件夹。选择本身不扫描；点击“检查所选文件夹”才读取内容。
2. 复查候选项，选择一个或多个可用目录。默认支持当前用户 `~/Library/Caches` 的直属缓存目录；其他位置需要直属目录内具有标准 `CACHEDIR.TAG` 签名，并且不在 Git 树内。
3. 点击复查，查看每个完整目标路径、全部子项清单、候选依据及逻辑大小。缓存位置或标记不能证明内容可丢弃；确认已停止相关应用／构建／同步，并确认所有选中内容可以重新生成。
4. 明确确认后，只把这个固定批次移入原生 macOS 废纸篓。逐项报告结果，遇到错误或取消停止后续项目。
5. 需要恢复时，读取恢复记录，重新复查并确认原路径恢复。原目标已存在时拒绝，不覆盖、不合并。
6. 需要释放存储时，在单个已完成的缓存记录中选择“复查永久删除”。再次展示精确缓存与完整内容清单，勾选不可恢复说明，再点击永久删除。此操作不能通过废纸篓或 MoeKit 撤销，不清空其他废纸篓项目。

移入废纸篓不释放缓存占用的存储。永久删除确认的是逻辑目录项移除；打开的文件、其他硬链接、APFS 快照／克隆可能保留物理块，因此不会把报告字节数显示成已释放的实际空间。应用也可能重新创建缓存并重新下载内容，首次运行可能变慢。

## 支持范围

- 普通当前用户、内置本地 APFS、无符号链接的目录祖先、可完整读取的目录清单
- 清单中的符号链接只作为链接处理，永不跟随目标；已确认路径之外的硬链接别名不会删除
- 每批最多 16 个缓存、总计最多 25,000 个清单项目；一次检查共用 45 秒／25,000 项预算。超限保持未知／不可操作，不把部分清单当作完整授权
- 永久删除另有最多 96 个目录的描述符预算与当前 FD 限额预检，超限在确认前拒绝
- 系统／安全类缓存、MoeKit 自身控制目录、废纸篓整体、项目／worktree／Git 元数据、常见凭据名、云端占位或未知权限／ACL／卷状态不开放
- 通用 Git 项目的 `build`、`dist`、`target`、`node_modules` 不因名字而获得删除权限；缺少包括 HEAD 的可靠跟踪内容证明时保持保护

这是 MoeKit 原创的原生文件操作适配器。Mole 提供独立的真实分析能力；此处没有运行 `mo clean`、`mo purge`、卸载或维护命令，也没有复制上游 GPL 实现。官方 V1.57.0 的 clean 明确不再支持 `--select`／`--categories`／`--exclude`，purge 的公开接口不会消费 GUI 的固定选择清单，不能把勾选项目偷偷映射为广域清理。

## 确认与恢复实现

准备计划只读，不创建恢复目录或锁。每个计划固定目标、完整元数据／链接清单、项目保护快照和上下文，120 秒过期，只能使用一次。Demo、目录／选择／项目保护改变、取消和重新检查均使旧确认失效。

确认后取得私有协调锁与项目目录共享锁，重验全批次，然后逐项用同设备 `RENAME_EXCL` 捕获到私有操作目录，重新验证整棵树才调用原生 Trash。捕获到不匹配对象时保留，不送入 Trash。路径、完整清单和编号状态记录仅保存在 `~/Library/Application Support/MoeKit/CacheRecovery`，不会自动清扫或重放。每次状态写入都使用 no-follow、O_EXCL、完整写入和持久化；写入失败锁定本次记录写入器，界面不把未持久化结果作为新的恢复／删除授权。

永久删除仅接受已完成且内容未改变的本应用 Trash 记录。再次捕获并验证整棵树后，按已保存清单逐个把叶项目／已空目录移入私有 `delete-entry-NNNNNN` 槽，验证捕获身份后才移除。编号对应不可变清单的零基索引；中断时可据此定位保留项。新出现的路径绝不加入删除范围。部分删除或未知结果保持可见，永不自动重试。

这些机制面向用户已停止工作负载的普通协作式本地使用。它们不是 OS 沙箱，不会阻止持有旧文件描述符的进程继续写入，也不承诺抵御恶意同 UID 进程干预私有暂存目录。原生 Trash 使用 URL；错误捕获在检测前可能有短暂位置变化，但检测到的不匹配对象不会进入不可逆移除。出现未知结果时先检查记录中的精确位置，不要重复操作。

## 验证

- 原生测试仅使用独立 UUID、标记字节与设备／inode 验证的测试目录，保留外部哨兵，绝不读取或清理真实用户缓存
- 普通测试使用独立临时“废纸篓”；真实 macOS Trash／恢复仅在 GitHub hosted runner、专用 opt-in 与完整身份门槛同时满足时运行
- CI 要求精确源码 SHA 的肯定运行证据，跳过测试不会满足验收。实际永久删除只作用于明确归属的测试清单
- 源码静态检查不是 Swift 编译／原生测试。完整窗口、键盘、VoiceOver 和真实用户目录权限仍需单独人工验收
