# MoeKit development conventions

## Product and current milestone

MoeKit is a native macOS home for a personal CLI toolbox. Projects, Tools and Tasks are the primary workspaces; Mole is one built-in module, not the app's whole identity. Prefer SwiftUI and AppKit with SF Symbols for interface icons. Use the approved custom artwork for the app icon.

The first source milestone implements navigation, explicit demo fixtures, bounded read-only project discovery, project-catalog persistence, a compiled-in tool registry, and Mole JSON report import. It additionally supports verified Mole directory analysis after per-run scope/cache-write confirmation, and one separately confirmed native operation: a directly listed local Downloads .dmg may move to macOS Trash with a private receipt and separately confirmed no-overwrite restore. Arbitrary CLI execution, broad Mole cleanup, package removal and project deletion remain unavailable. The Git cleanup adapter delivered in preview.9 supports separately confirmed recoverable retirement of a strictly verified clean linked worktree and removal of a fully merged loose local branch; it does not free space or permanently delete files. Read README.md and Documentation before making changes. Distinguish authored, built, tested and manually verified; never fabricate success or describe example data as a real result.

## Engineering

- Swift 6, macOS 15+, Tuist 4.148.3, SPM dependency management. Third-party runtime dependencies are exactly pinned Sparkle 2.10.0 and SwiftTerm 1.20.0 at commit `5d14406844143538cd8f8851d2d8a67c1fe443e5`. SwiftTerm is TerminalView only; its LocalProcess is forbidden. Sparkle's signed-feed updater is a separately reviewed app replacement path; do not broaden tool/cleanup execution permissions.
- UI/coordinator state is @MainActor and @Observable. Blocking IO belongs off MainActor. Cancel obsolete work and do not let stale results cross real/demo mode boundaries.
- No arbitrary shell-string execution, arbitrary CLI commands, project scripts/hooks, automatic CLI installation, privileged helper, or unconfirmed user-target mutation. Only a reviewed-catalog Mole analyzer or an explicitly acknowledged current-core bottle-verified major-1 analyzer, the separately confirmed fixed Homebrew Mole update/upgrade sequence below, the fixed read-only system disk-image inventory helper, GitObjectInspector's fixed version/object operations, and GitRemoteTransport's separately authorized fixed HTTPS operations against app-owned configuration-free object snapshots may execute. Git internal dispatch of the fixed compiled credential helper is the sole limited shell-dispatch exception; no repository or user command strings enter it. Git never receives a live repository or worktree path; only a temporary copy of an installed Apple-signed Git binary may be used, never bundled or downloaded. Explicitly confirmed, unprotected current-user process identities may receive SIGTERM via SDK audit-token signaling; SIGKILL requires separate fresh confirmation after observed non-exit. For user-selected processes there is no PID-only/name/group/descendant signal fallback; browser/session ownership remains unproved. Analyzer temporary writes and cleanup stay explicit and app-owned. Native single-DMG Trash/restore requires fresh scope, identity, ACL, catalog and use checks plus a one-use confirmation; no automatic recovery, overwrite or permanent deletion is allowed in that installer adapter. App initialization must not scan, read recovery records, create journals or move files.
- Discovery is scoped to a user-selected directory, has explicit budgets, does not follow symlinks, and does not infer Git cleanliness from HEAD. Unreadable and unknown states remain visible.
- Mole cleanup has no selected-path execution contract. Do not connect GUI selections to unbounded clean/purge commands. Old JSON without coverage is unknown, unavailable size is not zero, and overview totals may overlap.
- Test filesystem operations only in unique temporary fixtures. Do not run deletion tests against real projects.
- Original implementation only: do not copy GPL/AGPL application or CLI source. The project license remains undecided.

## Mole compatibility and controlled upgrade

- Read Documentation/Mole-compatibility-and-upgrade.md and Documentation/Mole-analysis-execution-design.md. Keep declared version, verified artifact provenance, and exact-head test evidence separate. A version string or Homebrew receipt does not grant execution. The planned `latestTestedVersion` identifier is not test evidence by itself; exact-head native fixtures remain a merge/release gate.
- Prefer the existing managed installation. Homebrew Mole 1.50.0 lacks the `scan_status` contract introduced in 1.56.1; explain the upgrade requirement rather than defaulting to a parallel older analyzer. Never automatically downgrade a newer version or execute an unknown file to probe its version.
- The reviewed catalog contains official 1.57.0/1.58.0 for both supported architectures and one exact ARM64 Homebrew 1.58.0 artifact. Opt-in online verification may compare a current homebrew/core bottle only after validating the complete downloaded bottle, full archive and exact regular analyzer member. No extraction, install, execution, local-data upload or persistent proof. Any additional eligible major-1 build requires separate per-analysis untested acknowledgement and produces view-only downstream authority; no live-result selection token.
- The only package-manager operation is one explicit new review of a fixed standard Homebrew executable, `update`, then `upgrade --formula mole` after a normal successful first phase and owned-group cleanup. Both exact commands must be displayed before a genuine focused Return/keypad Enter consumes the plan. Paste, programmatic input, terminal replies, sheet opening, reopening and key repeats cannot launch it. No shell-string or arbitrary-command editor, sudo, installation, automatic retry, rollback or downgrade.
- The original OperationTerminal helper owns the PTY and acknowledged process group; SwiftTerm only renders and forwards explicit input. Status comes from the separate supervisor pipe, never terminal text. Preserve phase-tagged input, escape filtering, bounded output/cancellation and uncertain/partial results. Hold task and app-update ownership until actual helper settlement. Recheck installation after every settled operation; command exit zero is not analyzer compatibility proof.
- `brew update` can update Homebrew itself; the upgrade can alter Mole/dependencies using real HOME and installed Homebrew state. This is not a sandbox. Retain the documented final pathname-exec race and escaped-descendant limits. Never use or mutate a user's Homebrew installation for tests. Synthetic fixtures, exact-head macOS compilation/signing/tests and native keyboard/VoiceOver review remain distinct evidence.

## Confirmed native cache cleanup

- Sources/Cleanup is a separate original native adapter: explicit multi-cache inventory and Trash, receipt-backed original-path restore, and an independently confirmed irreversible selected-receipt removal. Never wire selections to broad Mole clean/purge.
- Protect project/Git/credential/control namespaces and outside neighbors. Cache location or CACHEDIR.TAG is evidence only, never authorization. Links are leaves, not traversal. No general Git artifact deletion without tracked-content proof.
- Permanent removal exists only in CleanupPermanentRemoval.swift: immutable manifest, fresh private per-entry capture and identity checks, and separate action-time UI confirmation. Cache recovery itself never empties Trash. Sources/Trash separately supports current-user home Trash selected deletion and a typed-confirmed exact snapshot clear; it reuses the sink for files, links and directories. No external-volume or other-user Trash clearing is allowed. No automatic retry after partial or uncertain outcomes.
- Test mutations only in unique marker/identity-owned fixtures. Actual native Trash fixtures require hosted-runner opt-in, production path/volume guards and affirmative exact-head evidence. Never test against real user caches.

## Confirmed AI worktree finish

- Source changes are not complete because an AI says so. Inspect actual index/tree/files/OIDs; report project tests as not run. Native fast-forward supports a clean primary target checkout or an unchecked-out local target; no non-fast-forward merge, hidden stash/reset or project test execution.
- Local merge, credential/network inspection, exact remote push, and worktree retirement are separate approvals. Retain original target files/index/ref and phase records; partial application keeps recovery locks and never rolls back over later data automatically.
- HTTPS transport sees only a private object snapshot and fixed copied Apple-signed Git/HTTPS/osxkeychain tools. Do not read repository/global helper, URL, proxy or hook settings. The app-owned compiled pre-push gate pins exact URL/ref/advertised old/source; push stays non-force. The fixed credential wrapper permits get only for approved host/path and never stores or erases credentials.
- Unknown remote outcomes require separately requested read-only reconciliation, never blind retry or automatic retirement. No branch creation/deletion, fetch, redirect, password prompt, credential logging, real Keychain retrieval in tests, or authenticated public test push.
- GitRemoteTransport is one explicitly allowed original bundled helper; installed Apple binaries are temporary runtime copies only and never release assets. Update exact helper code/signing/archive allowlists and both-architecture tests when this boundary changes.
- Test local mutations and bare/loopback transports only in unique owned synthetic fixtures. Exact-head macOS native evidence is required; portable parser/helper checks do not establish Swift compilation or GUI acceptance.

## Confirmed local Docker cleanup

- Sources/DockerCleanup is a separate original Engine API adapter. It connects only after an explicit user request to one fixed local Unix socket; it does not read CLI contexts/configuration/credentials, run Docker CLI/plugins, start daemons or change permissions.
- Exact image/container ID operations require a fresh one-use confirmation and fresh daemon, socket and all-container reference evidence. Images referenced by stopped containers stay protected; no force, parent pruning, implicit image selection, or volume deletion is allowed.
- Whole-unused-build-cache pruning is a separately labelled daemon-wide category action with a distinct acknowledgement, not selected-row deletion. Never substitute system prune or broaden it to another builder/context.
- Test actual Docker mutations only on the independently started marker-owned CI fixture daemon, never the default/user daemon. Ordinary macOS tests use in-memory or unique local socket fixtures. Preserve cancellation/partial/unknown results and report only verified outcomes.

## Native Trash management

- Sources/Trash accepts only the fixed current-user home .Trash. Read Documentation/Trash-management.md for budgets and scope; do not wire arbitrary paths or external .Trashes to it.
- All deletions require immutable full-path manifests and a fresh one-use irreversible UI confirmation. Clear-snapshot additionally requires the literal EMPTY; new arrivals never expand an old confirmation.
- Retain uncertain/substituted objects, interrupted payloads, per-entry slots and private records. No automatic retry, rollback, overwrite or history purge. No real-user Trash tests: use uniquely created owned temporary fixture trees only.

## Verification and publishing

Use Scripts/verify-source.py for structural checks, then the documented macOS build/test workflow. Python checks are not Swift compilation. Report failing, unrun and passed stages separately. CI may build an ad-hoc preview artifact; public releases and signing use separately reviewed workflows. Never commit credentials, P12 data, passwords, Team IDs, personal signing identities or keychains. No secrets in pull-request jobs; no pull_request_target execution of an untrusted head. A signature is not Apple notarization.
