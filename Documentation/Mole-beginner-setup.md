# Mole 新手设置与自动检测

此页描述新增源码工作流；是否已交付请以对应发布说明为准。

## 从零开始

1. 打开 Tools → Mole → Space →「使用 Mole 分析…」。MoeKit 自动检查少量常见安装位置，不需要先找到 `analyze-go` 文件，也不会执行 `mo`、安装程序或扫描要分析的文件夹。
2. 如果显示「可以开始分析」，选择 Downloads 或其他文件夹，再点击「复查分析…」。阅读范围及私有临时缓存说明后，才可明确开始分析。
3. 如果未找到或不兼容，展开同一窗口的安装步骤。按 `⌘ Space` 打开 Spotlight，输入「终端」并打开；查看官方发布和下载命令后，复制到终端自行运行。
4. 等待终端输出 `Mole analyzer ready`。回到 MoeKit 点击「重新检测」，然后选择文件夹。复制按钮只更新剪贴板，应用不打开终端、不安装、不下载、不提权。
5. 自定义安装位置或旧版指引创建的随机目录，可在「高级：分析器文件与检测详情」中手动选择文件；选择不代表已通过验证。

下载命令只取得 MoeKit 当前支持的独立分析器，不安装完整 Mole 工具，也不替换 Homebrew 或现有官方安装。完整 Mole 项目与 MoeKit 是不同软件。

## 为什么检测到 Homebrew 后还会不兼容

当前执行器只信任 V1.57.0 原始官方发布分析器的精确字节，版本、大小和 SHA-256 常量与实际执行器共用。[Homebrew 的 V1.57.0 formula](https://github.com/Homebrew/homebrew-core/blob/3e0ad2772181b2347f25b7f47caeb7882db4b9d7/Formula/m/mole.rb) 删除预编译文件并重新构建 Go 二进制，因此相同版本号也不能替代摘要校验。2026-10-06 核对时，上游及 Homebrew 已更新到 V1.58.0；`brew install mole` 并非此版本 MoeKit 的兼容修复。

[官方 V1.57.0 安装器](https://github.com/tw93/Mole/blob/V1.57.0/install.sh) 在下载失败时可能回退到其他发布或本地构建，还可能处理既有 Homebrew 安装。这里不运行该安装器，而是提供固定发布文件的透明手动下载命令。没有接受新版本、新签名或 Homebrew 构建的隐式信任扩展。

## 检查范围和状态

只在用户打开分析窗口或点击重新检测时检查，启动应用及 Demo 模式均不读取这些安装位置。固定最多 10 个候选位置，不搜索 PATH、不递归遍历、不列出主目录、不执行版本命令或 Shell 包装脚本：

- 新指引位置：`~/MoeKit-Mole-V1.57.0-arm64/analyze-go` 或 `~/MoeKit-Mole-V1.57.0-x86_64/analyze-go`，按当前应用架构选择
- 官方安装器默认：`~/.config/mole/bin/analyze-go`
- Homebrew：`/opt/homebrew/opt/mole/libexec/bin/analyze-go`、`/usr/local/opt/mole/libexec/bin/analyze-go`；只接受其祖先别名解析到对应 `Cellar/mole/<version>/libexec/bin/analyze-go` 布局，仍须通过同一字节校验
- 命令存在性观察：`/opt/homebrew/bin/{mo,mole}`、`/usr/local/bin/{mo,mole}`、`~/.local/bin/{mo,mole}`；只观察元数据，不读取或运行包装脚本

状态区分：

- **可以开始分析**：至少一个直接分析器满足精确发布字节、架构、普通文件、权限、所有者和隔离标记检查。自动选用首个匹配文件；实际准备及执行还会再次验证，不直接启动分析。
- **未找到分析器**：已检查的位置均未找到。不能宣称整台 Mac 未安装，自定义位置仍未知。
- **分析器不兼容**：观察到文件但不符合精确发布或可执行文件要求。其他版本、Homebrew 构建、架构不同和权限问题不会变成“未安装”。
- **分析器未验证**：仅发现包装命令、最终符号链接、特殊文件、无法读取、路径变化或隔离标记；不自动选用。原因可在高级详情中检查。

至少一个通过验证时优先显示可用；否则存在不兼容文件时显示不兼容，再否则存在未知证据时显示未验证。每个候选状态均保留。不会根据目录名或脚本中声明的版本号证明安全。

## 下载与重试边界

命令先在主目录创建唯一私有 `MoeKit-Mole-download.XXXXXX` 文件夹，下载到这里并核对大小及 SHA-256，通过后才添加执行权限。随后独占创建固定版本/架构目录，再以不覆盖已有文件的硬链接放置 `analyze-go`，使重新检测能找到它。两个路径指向相同内容，不产生第二份数据副本；原下载目录保留，应用不会自动清除。

如果固定目录已存在，命令保持其原样并停止，提示返回重新检测。若它不是可用分析器，用户可先在 Finder 中把该目录移到别处再重试，或高级手动选择。下载失败时不会提前创建固定目录；失败的私有下载目录保留供检查。不会覆盖用户已有文件、删除旧安装、修改 PATH、运行下载文件、请求 sudo、移除隔离标记或重新签名。

浏览器下载可能带 macOS 隔离标记；应用拒绝此类文件。不要换下载途径规避已出现的系统警告。工具的普通用户权限模型和每次分析确认保持不变，见[执行设计](Mole-analysis-execution-design.md)。

## 生命周期与验证

检测在独立 actor 中运行。固定路径数量及每个文件的受支持大小限制读取量，但文件系统调用可能等待，不能承诺硬超时。取消、关闭、Demo 切换使旧结果失效；在检测真正返回前保留任务所有权，不能启动第二个检测或分析。重新检测保留选择的文件夹，但清除旧分析器、确认计划和结果。选择自定义分析器后明确显示未验证，只有原执行器才能准备确认计划。

测试仅使用唯一临时目录和合成 provider，覆盖正确/错误摘要、Homebrew 布局及逃逸链接、包装脚本、FIFO、符号链接、隔离、权限、重复点击、取消、Demo 快速切换、重新检测、过期确认和手动选择。已有官方分析器 CI fixture 增加“发现 → 验证 → 原执行器分析”链路。英文/简中、深浅色与两种尺寸的 owned-view 渲染增加就绪、未找到、不兼容、未验证和高级状态；这些是实际 SwiftUI 渲染证据，不等于用户 Mac、键盘、VoiceOver 或完整交互验收。
